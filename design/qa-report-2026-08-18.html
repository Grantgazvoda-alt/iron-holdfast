3 Findings

F-001 Floating stone terrain sprites (top-left quadrant) High · Visual

In the live build, the top-left area of the map (above the western forest strip, near the grass/forest/water boundary) renders grey, stone-like “L-shaped” patches that float over the tree and grass tiles — disconnected from the terrain logic (no buildings or enemies exist there). They don’t affect gameplay but visibly degrade the “realistic, polished” presentation target.

DeviationArtifacts remain visible and static; expected continuous terrain texture breaks the painterly seam between forest and grass.
Perceived riskCosmetic; limited to visual polish at launch — but High because this ships against the current visual-art upgrade goal.
ExpectedNatural painted base everywhere (grass blades, forest canopy, rock outcrops from the painter).
ActualStone-shaped grey patches overlay tree/grass tiles in the top-left.
Reproduction
  1. Open https://iron-empire.higgsfield.app
  2. Click “Begin the hold”
  3. Skip the tutorial (or let it run)
  4. Pan/zoom to the top-left corner (north-west of the keep)
  5. Observe the grey “stone quarry-like” textures floating over trees/grass
Status: FIXED (2026-08-18) — committed as 0e25153 (project), 49b70dc (GitHub iron-holdfast), e4a012f (GitHub iron-holdfast-source). Root cause: painter decals exceeded the 64px tile boundary (outcrops to x 71px, boulders to 68px), bleeding grey stone onto adjacent tiles. Fix: rock outcrops, ore veins, and gold nuggets now spawn strictly in-tile (≤ 62px). Pending: visual retest once the fixed build is deployed live.
F-002 Frozen game clock observed in browser — resolved, no server defect Resolved
ObservationOn-screen timer stayed fixed at “8:39”, wave countdown static, wood stuck at 35 for minutes, pause label never flipped.
DiagnosisServer probes on the same endpoints show normal ticking: nextWaveIn decrements per tick, time advances every 0.5s, paused:false. A raw WebSocket session on a fresh room reproduced normal ticking before any build action.
ConclusionTest-harness/browser anomaly (F-003) — not a game defect.
If a player reports a frozen clock: treat as client-side reconnect (reconnect loop already guarded in code) or live-server, not the sim engine.

DescriptionThe automated browser repeatedly navigated away to a landing-page domain (settup.e-pos.id) mid-test; canvas lookups failed until the game URL was restored.
Product impactNone — an artifact of the shared/managed browser test environment, not game code.
Mitigation(1) re-assert game host before each measurement, (2) prefer raw WS protocol probes for timing/state, (3) use the browser only for DOM/render/UI checks.
